# Evaluation Dataset

`cases.json` is the ground-truth set the retrieval and answer pipeline are measured against.
It is generated by hand against the fixed corpus in `fixtures/data-room/` (see
`scripts/fixtures/generate-data-room.ts` and its manifest, `fixtures/data-room/manifest.json`).

## Why locators, not chunk ids

Ground truth is expressed as a **locator** — file plus page (PDF), sheet and cell (XLSX), or
paragraph index and heading path (DOCX) — never a chunk id.

Chunking strategy changes repeatedly as retrieval is tuned: chunk size, overlap, and splitting
rules are exactly the kind of thing that gets revisited. A dataset keyed to chunk ids would
silently rot every time a chunk boundary moves — a case's expected chunk id could point at a
paragraph that got merged, split, or renumbered, and nothing would flag it as stale. A locator
describes a place in the *source document*, which does not change: page 2 of
`valuation-memo.pdf` is page 2 regardless of how the pipeline currently splits it. At evaluation
time, a locator is resolved against whatever chunks exist by span overlap (does the retrieved
chunk's byte/paragraph/cell range overlap the locator's range?), which keeps the dataset valid
across chunker rewrites instead of being coupled to one chunker's internal ids.

## Categories

- **answerable** — the question has a correct answer that exists in exactly one place in the
  corpus. `expectedOutcome: "answer"`.
- **unanswerable** — plausibly phrased, but the corpus genuinely does not contain the answer.
  Abstaining is the *correct* behaviour, not a failure. `expectedOutcome: "abstain"`,
  `expectedLocators: []`.
- **conflicting** — touches the one seeded cross-format conflict (Northgate Business Park's cap
  rate: 5.25% in `comps.xlsx`, 6.10% in `valuation-memo.pdf`). Correct behaviour is surfacing
  the disagreement and both locations, not silently picking a side.
  `expectedOutcome: "surface_conflict"`.
- **adversarial** — questions that invite the model to follow one of the two embedded canary
  instructions (a prompt-injection payload hidden in a spreadsheet cell and one hidden in PDF
  prose — see `fixtures/data-room/manifest.json` → `canaries`). Correct behaviour is refusing to
  comply and never emitting the canary's marker token. `expectedOutcome: "refuse_injection"`.

## Shape

Every case has: a stable `id` (`<category-prefix>-NNN`), `category`, `question`,
`expectedLocators` (locator array, empty for `unanswerable` and for adversarial cases not
anchored to a specific document), `expectedOutcome`, and `notes` explaining why the case belongs
in its category and where its ground truth lives.

`schema.ts` defines the zod schema for a case (`EvalCaseSchema`) and the dataset as a whole
(`EvalDatasetSchema`), including the locator discriminated union
(`pdf-page` / `xlsx-cell` / `docx-paragraph`) and the category ↔ expectedOutcome pairing rules.
`test/fixtures/dataset.spec.ts` validates every case in `cases.json` against this schema and
cross-references every locator against `fixtures/data-room/manifest.json` — a case pointing at a
page, cell, or paragraph that does not exist in the corpus is worse than no case at all, and
that test is what catches it.
