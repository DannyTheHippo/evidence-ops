Applies to the SPA under `web/`. The NestJS API under `src/` follows `nestjs.md`.

Stack: React 19.2, react-router-dom 7.18, vite 8, vitest 4.

Before adding a component, read `web/src/pages/LoginPage.tsx` and `web/src/App.tsx` and match them exactly. `web/src/pages/` holds twenty pages, each carrying a colocated `*.test.tsx`, so "match the sibling" is always a short read; inventing structure ahead of need is the main failure mode here.

# React SPA Patterns

## What this SPA does not have

Stating these so they are not reintroduced by reflex:

- **No state library and no data-fetching library.** No Redux, Zustand, React Query, or SWR. Component state is `useState`; server calls go through the hand-written client in `web/src/api/client.ts`.
- **No `AuthContext` and no client-held credential.** The session is an HttpOnly cookie the browser sends on its own; the SPA stores no token. `ensureSession()` (`web/src/lib/auth.ts`) probes `GET /auth/me` once and caches the answer in a module-scope variable; `useSession()` (`web/src/lib/use-session.ts`) is the reactive shell over it. Both fail **closed** — a rejected probe resolves to `anon`, never to a stale "probably still logged in". `RequireAuth` and `RequireAdmin` in `AuthenticatedRoutes.tsx` read that cache and are the whole client-side authorization story; each server route carries its own guard, which is the actual boundary.
- **No `import.meta.env` and no `VITE_*` variables.** The API base is the relative constant `const API = '/api/v1'`. Vite proxies `/api` in dev (`web/vite.config.ts`); nginx proxies it in prod (`web/nginx.conf`). **FORBIDDEN** to hardcode `http://localhost:3000` in SPA code — it breaks the production build silently.
- **No component library, no CSS-in-JS, no Tailwind.** See `styles.md`.

Introducing any of the above is an architecture decision: raise it, do not slip it in with a feature.

## Components

- Components that need to expose a ref take it as a plain `ref` prop (React 19 passes `ref` like
  any other prop) — not `forwardRef`. Declare it explicitly in the props interface, since
  `ButtonHTMLAttributes` and friends don't type it; see `Button.tsx` and `IconButton.tsx`.
- Function components with hooks only. **FORBIDDEN** to introduce class components, with exactly one
  sanctioned exception: `web/src/components/ErrorBoundary.tsx`. React exposes error boundaries only
  through `getDerivedStateFromError`/`componentDidCatch`, which have no hook equivalent, so the
  alternatives are a class or a fourth runtime dependency. That file is the whole exception — a
  second class component anywhere is a review finding, and the boundary itself holds no logic beyond
  catching, resetting on route change, and rendering the fallback.
- Pages live in `web/src/pages/` as `PascalCase.tsx` with a default export and a colocated `PascalCase.test.tsx`. A page with genuinely separable responsibilities may split into a `pages/{name}/` directory instead: the route file re-exports the default, and each extracted piece carries its own colocated test.
- `web/src/components/` splits three ways: `components/ui/` holds the shared primitives (`Button`, `IconButton`, `Badge`, `Skeleton`, `EmptyState`, `Field`, `Select`, `Textarea`, `Input`, `PasswordRules`, `Table`, `Dialog`, `ConfirmDialog`, `Menu`, `Pager`, `FilterBar`, `SortableHeaderCell`, `SplitView`, `Timestamp`, `CopyButton`, `Toaster`, `toast.ts`) — `Select`, `Textarea`, and `Input` compose `Field` for the labelled-control shape rather than reimplementing it — reach for `Pager` before hand-rolling paging on a new list page, every existing paginated page already uses it; `ConfirmDialog` before a bespoke confirmation modal for a destructive or irreversible action; `FilterBar` before a bespoke filter `<form>`, it owns the submit-on-Apply/Clear behaviour so a filtered list stays driven by explicit submission rather than firing a request per keystroke; `SortableHeaderCell` before a hand-rolled sortable `<th>`, it owns the `aria-sort` and accessible-name wiring a caller would otherwise have to reproduce; `SplitView` before a bespoke two-pane layout, as the review queues already do; `CopyButton` before a hand-rolled "Copy" button, it owns the async Clipboard API and the copied/failed announcement. `components/shell/` holds the app shell composed by `App.tsx` (`Sidebar`, `Topbar`, `ConnectionStatus`, `ThemeToggle`); the `components/` root holds `RecordListPage.tsx` (the shared list-page scaffold, detailed below), `AnswerWorkspace.tsx` (the answer surface shared by `AskPage`'s live view and `AnswerDetailPage`'s historical view — status badge, in-flight/failed notices, and the admin-only run cost, wrapping `AnswerView.tsx`'s outcome rendering), `ApprovalDecisionDialog.tsx` (the approve/reject dialog shared by `ApprovalsPage`'s detail pane and `WorkflowRunPage`'s inline timeline), `AnswerView.tsx` (rendering `ProvenanceRail.tsx` and `VerificationLedger.tsx` for a grounded outcome, `ConflictValueCompare.tsx` for a `conflicting_evidence` outcome — `ProvenanceRail` is also rendered directly by `SearchPage`, and `ConflictValueCompare` directly by `ConflictsPage`) plus `ErrorBoundary.tsx` (the one sanctioned class component, wrapping the routed area from `App.tsx` **outside** its `Suspense` boundary so a failed dynamic chunk import renders the fallback rather than an empty `#root`) and the shared `icons.tsx` set. Every one carries its own colocated test. `web/src/lib/` holds the non-component helpers: `auth.ts`, `use-session.ts`, `use-event-stream.ts`, `breadcrumbs.ts` (module-scope publish/subscribe for a page's breadcrumb trail, the same shape `use-event-stream.ts` uses for stream status — `useBreadcrumbs(trail)` publishes, keyed on the trail's serialized content rather than its identity since a caller's inline array literal gets a new identity every render; `useBreadcrumbTrail(fallback)` is the reactive subscriber `Topbar` and `App.tsx` both read, the latter for `document.title`), `use-pending-counts.ts` (the Review queue badge counts — conflicts and approvals — behind `Sidebar`; a count that fails to fetch resolves to `null` rather than breaking the nav), `use-url-state.ts` (round-trips a list page's filters/sort/paging through the query string — reach for it before hand-rolling URL-backed state on a new list page), `use-answer-run.ts` (owns an answer's whole lifecycle from `answerId` alone — the initial GET, the SSE subscription, and the poll-until-terminal fallback once the stream gives up — shared by `AnswerWorkspace`'s two callers: `AskPage` seeds it with its own optimistic snapshot, `AnswerDetailPage` always fetches), `use-answer-enrichment.ts` (the document-title and conflict-chunk enrichment `AskPage` and `AnswerDetailPage` both need for a completed answer), `use-copy-to-clipboard.ts` (the async Clipboard API wrapper behind `CopyButton`), `use-object-url.ts` (fetches a `Blob` keyed on a caller-supplied key and exposes it as a `blob:` object URL, owning the one `URL.revokeObjectURL` call so no page has to remember it — behind the document workbench's file preview), `use-source-sync.ts` (the sync-now action and poll-until-terminal-run hook shared by `SourcesPage`'s one-instance-per-row and `SourceDetailPage`'s single instance), `document-index.ts`, `locator.ts`, `citation-link.ts` (`workbenchHref`, the document workbench's deep-link query-string scheme — every citation and trace-chip link builds through it rather than hand-assembling the URL), `identifiers.ts` (the shared shortening/labelling of digests, uuids and workflow types — a raw identifier rendered in full anywhere in the SPA should be reaching for this instead), `format-interval.ts` (names a sync cadence in its coarsest clearing unit), `format-timestamp.ts` (the relative-phrase and full-local-timestamp formatters behind `Timestamp` — a rendered date uses `Timestamp`, never `new Date(...).toLocaleString()`, so both formatters share one "no value to show" fallback instead of every call site inventing its own), `workflow-runs.ts` (the shared `isTerminalRun` check), `answer-status.ts` (`RUN_STATUS_TONE` plus `answerBadge`, which resolves an answer to its `{ tone, label }` pair — it returns the mapping rather than a rendered `Badge`, which is what lets a status vocabulary live in `lib/` at all, and why the labels are lowercase in exactly one place instead of three), `metric-labels.ts` (`useMetricLabels()` fetches the metric-id-to-label map once per browser session and caches it in module scope; `metricLabel` falls back to the raw id whenever `/metrics` has not returned it yet, or never will, rather than a placeholder like "unknown"). There is no `hooks/` directory — `use-session.ts` lives in `lib/`. Lift a page-local component only when a real second consumer exists, not preemptively.
- Colocate state with the component that owns it; lift only as far as a real common consumer requires.
- `RecordListPage` (`web/src/components/RecordListPage.tsx`) is the shared scaffold for a list page: header, an optional `actions` slot, an optional `filters` slot, an optional `error` string rendered as a page-level alert independent of `status`, a `status` union (`loading` | `blank` | `empty` | `ready`) that drives one body region — `ready` renders `children`, which carries no assumption about shape (a `<Table>` in a `.panel` on most pages, a split view on the two review queues) — and an optional `footer` rendered after that region regardless of `status.kind`, which is where a page's `<Pager>` belongs so it stays reachable under every status including `empty`. `error` is not a `status.kind`: a failed refresh renders the alert alongside `ready`'s existing rows or `empty`'s state rather than blanking them, and `blank` is the one status with no body of its own, for a first-load failure where `error` alone should render. A page whose `children` scrolls horizontally inside `.panel` — a wide table between 768px and 1023px, per the fallback documented in `primitives.css` — owes the scrolling element `tabIndex={0}`, `role="region"`, and an `aria-label` naming its contents: that scrollbar is otherwise invisible to assistive tech and unreachable except by mouse, `tabIndex={0}` makes the container a focusable stop so keyboard scrolling can reach it, and `role="region"` plus `aria-label` give that stop an announced name instead of an anonymous `<div>`. `RecordListPage` documents this contract but does not apply it, because only the page instantiating `children` knows which element actually scrolls.

## Data access

- All API calls go through `web/src/api/client.ts`. **MUST** add a typed exported function there rather than calling `fetch` from a component.
- The client already centralizes: `credentials: 'same-origin'` so the browser attaches the session cookie, the 401-redirect-to-login rule (`window.location.assign('/login')`, skipped for `/auth/*` so a failed login renders its own error), the FormData content-type exception, 204 handling, and `ApiError` with a `status`. Do not duplicate that logic per call site.
- Response interfaces in `client.ts` are generated from the API's OpenAPI document for every shape a route names as its response type (`npm run openapi:generate`, then `web`'s `openapi:types`, into the committed `web/src/api/openapi.json`/`schema.ts`) — a field the API adds, drops, or renames there is a `typecheck` error, not a silent drift. List envelopes, request DTOs, and the `Locator`/`AnswerOutcome`/`Citation` unions are not named by any route response and stay hand-written; update those in the same change as the API DTO they mirror, since nothing catches drift on them. See `docs/adr/0023-spa-types-generated-from-openapi.md` for the full boundary.

## Router

- `react-router-dom` v7, declarative `<BrowserRouter>` / `<Routes>` / `<Route>`. **Not** the data-router API — `createBrowserRouter`, loaders, and actions are not in use. One consequence worth knowing before promising a feature: there is no navigation-blocking API, so an unsaved-changes guard covers tab close and reload via `beforeunload` but cannot stop an in-app `<Link>` or the back gesture.
- **The route table is split across two files, and the split is load-bearing.** `App.tsx` statically imports only what an anonymous visitor can reach (`LoginPage`, `InvitePage`) and pulls everything else through a single `lazy(() => import('./AuthenticatedRoutes'))`. `AuthenticatedRoutes.tsx` statically imports all eighteen remaining pages plus `RequireAuth`/`RequireAdmin`/`NotFoundView`, so Rollup emits **one** chunk for the whole authenticated app rather than one per page — seventeen of those eighteen are wrapped in `RequireAuth` or `RequireAdmin`; `InvitationsPage` is the one exception, a bare `<Navigate>` shim to `/people` with nothing to guard. Adding a guarded route means editing `AuthenticatedRoutes.tsx`; adding a dynamic `import()` per page would fragment that chunk across a `listen 80` origin capped at six connections.
- New authenticated routes wrap their element in `<RequireAuth>`; admin-only routes wrap in `<RequireAdmin>`, which redirects a non-admin to `/`.

## Hooks

- **MUST** call hooks unconditionally at the top level.
- **MUST** keep `useEffect`/`useCallback`/`useMemo` dependency arrays exhaustive. Do not suppress `react-hooks/exhaustive-deps` without an inline justification naming the rule.
- `eslint` runs `typescript-eslint` `recommendedTypeChecked` here: floating promises are errors. Event handlers that call an async function use `onSubmit={(e) => void handleSubmit(e)}`, matching `LoginPage.tsx`.

# SPA Testing (vitest + Testing Library)

- Runner: **vitest 4**, configured inline in `web/vite.config.ts` (`test` key) — there is no `vitest.config.ts`. `environment: 'jsdom'`, setup at `web/src/test/setup.ts`.
- Test files are `*.test.tsx`, colocated with the component. Run with `npm --prefix web run test`.
- The `test` script runs vitest under `NODE_OPTIONS=--no-experimental-webstorage`. Node 26 exposes its own `localStorage` global, which shadows jsdom's inside the test environment and throws unless Node was given a backing store. `web/src/lib/auth.ts` touches `localStorage` at module scope, so without the flag every test that imports the API client throws on import, before any assertion runs. Any new SPA test lane needs the same flag.
- A test exercising `useEventStream` or an `EventSource`-backed page **MUST** install `web/src/test/fake-event-source.ts`'s `FakeEventSource` via `vi.stubGlobal('EventSource', FakeEventSource)` — jsdom has no native `EventSource`, so an unstubbed test only exercises the hook's undefined-`EventSource` fallback path.
- **MUST** import `describe`/`it`/`expect` explicitly from `vitest` — globals are not enabled.
- `@testing-library/jest-dom` is registered via its `/vitest` entrypoint in the setup file; `toBeInTheDocument()` and friends are available without a per-file import. That same file registers an explicit `afterEach(cleanup)`, because Testing Library's auto-cleanup only installs itself when vitest globals are on.
- **MUST** query by role, label, or text — never by class name or test id when an accessible query exists.
- A component using router hooks **MUST** be rendered inside `<MemoryRouter>`.
- There is no coverage threshold on the SPA. Absence of a gate is not permission to skip the test — a new page ships with a rendering test at minimum.
